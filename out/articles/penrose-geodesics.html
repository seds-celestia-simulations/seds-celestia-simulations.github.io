Penrose: Real-Time Geodesics in Schwarzschild Spacetime

July 19, 2026
14 min read
By SEDS Celestia Simulations

Weak-field lensing tricks break down near a black hole. Photon spheres, infinite-order Einstein rings, and horizon capture need the full geodesic equation — not a deflection-angle shortcut. Penrose is our answer: a modular GR framework that integrates those geodesics on CPU for science, and on GPU for interactive visualization.

Built by Harliv Singh, Anvay Shinde, Akshay Karuvathil, Aditya Melinkeri, and Hardik Bisht.

Why we built it

Computational astrophysics needs both trust and speed. Offline solvers can be precise but slow to explore. Screen-space hacks look cinematic but often skip the physics. Penrose keeps those concerns separate:

  • CPU pipeline (physics/) — reference implementation: metrics, Christoffel symbols, RK4 integration, CSV export, analytic benchmarks.
  • GPU pipeline (realtime/) — OpenGL + GLSL raymarcher: one null geodesic per pixel, solved in parallel inside the fragment shader.

Same physics story. Two backends. The CPU path is ground truth; the GPU path is the live window into curved spacetime.

State and integrator

Every trajectory is an 8-component state

S=(t, r, θ, ϕ, ut, ur, uθ, uϕ)\mathbf{S} = (t,\, r,\, \theta,\, \phi,\, u^t,\, u^r,\, u^\theta,\, u^\phi)S=(t,r,θ,ϕ,ut,ur,uθ,uϕ)

evolved with classical RK4 in the affine parameter. Local truncation is O(h5)\mathcal{O}(h^5)O(h5); global error O(h4)\mathcal{O}(h^4)O(h4) — enough to keep Killing invariants from wandering for long marches.

On the GPU we keep a fixed step. Adaptive schemes (RKF45 and friends) are nicer in flat regions but cause warp divergence across neighboring pixels. Fixed hhh trades a bit of step efficiency for SIMT coherence.

Singularities get practical treatment: polar reflection when θ\thetaθ crosses the axis, and hard termination once r<1.1 rsr < 1.1\,r_sr<1.1rs​ so divisions by (r−rs)(r - r_s)(r−rs​) never blow the shader. Escape at large rrr samples the skybox; disk hits read an SSBO of kinematic particles.

What real-time looks like

Each frame:

  1. Un-project every pixel to a world-space ray.
  2. Convert Cartesian camera rays to spherical geodesic state.
  3. March with GPU RK4 until horizon, disk hit, or escape.
  4. Color the fragment — black for capture, particle color for disk, environment map for infinity.

Workload is embarrassingly parallel. Adjacent rays usually share the same control flow until the shadow edge, where capture/escape splits the warp. Memory stays small: procedural geometry plus a single particle SSBO, well under tens of megabytes.

Disk debugging — real engineering

Accretion-disk visuals did not arrive free. Early SSBO / depth interactions produced artifact rings and broken disks. The team chased the bug in notes, compared broken vs underlying frames, then shipped the fixed path.

Takeaway

Pretty frames are a byproduct. Penrose prioritizes integrable equations, measurable error, and debuggable pipelines — then the image gets honest.

Limits (honest ones)

  • Schwarzschild only today — no Kerr spin yet.
  • GPU path is fp32; near-horizon rounding piles up over ~1000 steps.
  • Fixed step size struggles at the photon sphere without denser sampling.
  • Accretion disk is kinematic points, not radiative transfer.
  • No gravitational redshift or Doppler boosting in the color pipeline yet.
